- **Coding agent:** `merge_default_branch` and its merge commit now work on GitLab and Bitbucket apps too. On Bitbucket the commit has the branch and the default branch as parents; on GitLab, whose API writes one parent, rendimiento commits the resolution on the branch and on a passing branch `rendimiento/mezcla-…`, and merges the two through a merge request that closes by itself (a project that merges only by fast-forward or rebase, or always squashes, cannot take it).
- **Bitbucket:** a commit rendimiento writes (declared fixes, the coding agent) keeps an executable file executable, and its hash is the one Bitbucket says it wrote, not the branch's head after another push.
