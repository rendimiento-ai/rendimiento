- **Keys and settings:** the image registry, the DNS zone and target, the certificate issuer, the storage class, the ingress class and the public address change on the Environment page, each after its connection test (BuildKit pushes a test image and every node pulls it; the zone takes a test record; the issuer is ready; a test volume binds; the ingress controller runs; the address answers as this platform). «Change» is enabled only once the test passed for those values; nothing is saved when a step fails.
- **Keys and settings:** a changed setting is saved as a platform setting that wins over the ConfigMap's at start, and the platform's Deployments restart to use it (a minute or two). «Back to the ConfigMap's value» undoes it; `TESTED_SETTINGS=ignore` starts with the ConfigMap's values whatever was saved.
- **Volumes:** a volume that exists keeps its storage class when `STORAGE_CLASS` changes; new volumes take the new one.
- **Address:** `GET /api/identidad?n=…` answers a nonce signed with a key only the platform's processes have, so a new address can be proved to be this platform.
