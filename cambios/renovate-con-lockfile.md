- **Renovate:** with the GitHub App allowed only to read commit statuses, Renovate no longer tries to set its own (`renovate/artifacts` and the others). Setting the red `renovate/artifacts` status on a branch whose lockfile it could not update failed, and Renovate abandoned the repository as `repository-changed` right after opening the pull request, before reporting the lockfile's error. No `make deploy` needed: updating the platform is enough.
- **Renovate:** a lockfile Renovate could not regenerate (`package-lock.json`, `poetry.lock`…) is kept in the run's results per repository (branch, file, the tool's error lines), shown on the Add-ons page and the app's page, and appears on the Problems page as "Renovate could not update a lockfile", with what to do.
