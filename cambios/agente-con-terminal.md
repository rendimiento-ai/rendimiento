- **Coding agent:** a `run` tool runs any shell command (installs, tests, linters, git) in a sandbox pod with the repository at its branch and its uncommitted changes; the files a command changes become its changes, and it is told to run the tests touching its change before `commit_and_test`. Each command shows in the encargo's history; it costs no AI money, only time.
- **Coding agent:** the sandbox runs in the build namespace on worker nodes only, with no service account token, no secrets or platform environment, not root, all capabilities dropped, seccomp `RuntimeDefault`, a sized `emptyDir` workspace, 2 CPU / 4Gi, 15 minutes a command; it is kept for the encargo and removed when it ends, after 30 idle minutes, or by a janitor.
- **Coding agent:** a new NetworkPolicy, `isolate-sandbox`, lets sandboxes reach DNS and the public internet only (not the cluster, the nodes, the home network or BuildKit), and `isolate-builds` now leaves them out. The platform also makes it before any sandbox starts.
- **Coding agent:** on the AI page, **Run commands in a sandbox** turns the tool off for an organization (on by default). `CODER_SANDBOX=off` turns it off for the platform; `CODER_SANDBOX_IMAGE`, `CODER_SANDBOX_RUNTIME_CLASS` (empty: the cluster's default runtime; for gVisor or Kata later), `CODER_SANDBOX_CPU`, `CODER_SANDBOX_MEMORY` and `CODER_SANDBOX_DISK` tune it.
- **Deploy:** `deploy/` changed (the builds Role may now exec into pods, and the new NetworkPolicy): run `make deploy` once, or the tool answers that exec is not allowed.
