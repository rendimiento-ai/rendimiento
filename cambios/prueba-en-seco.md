- **En seco:** a post-deploy task can ask for `dryRun: true` (never with `service:`, refused), and so can `tests:`. On a branch that changes only those checks (their definition in `rendimiento.yaml`, or the build whose image holds them, such as `e2e/`) and not the app, they run once the branch's steps passed: against the release already published, in the app's namespace, as Jobs named `seco-…`. With nothing published yet, or when the branch changes the app too, nothing runs and the run says why.
- **Run page:** the checks run en seco show in a dashed section of their own, *En seco, against the published release #N*, each with its log. A failure only warns: the run says **Passed, with a warning**, its GitHub check concludes `action_required` (Renovate's automerge waits), rendimiento does not merge it by itself, and the button says **Merge anyway**, which leaves a note in the Ruta.
- **Database:** migration `0059_prueba_en_seco.sql` adds `runs.dry_release`, `runs.dry_note`, `runs.dry_failed` and the `run_dry_tasks` table (only adds).
