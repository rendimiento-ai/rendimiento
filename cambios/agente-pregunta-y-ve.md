- **Coding agent:** it can ask you (`ask`) instead of giving an encargo up when it needs your word: it commits what it has, stops without spending, and the question shows first on Ruta → For you and in the bell. **Answer and let it go on** resumes it on the same branch with your answer; **Pass it to my agent** gives it to your own agent with the question, and so does a question nobody answers in 3 days. Only a person signed in can answer (`POST /api/encargos/{id}/answer`, `/pass`).
- **Coding agent:** read-only tools for the encargo's own app only: `runs` (step durations and status, by branch or step), `step_log`, `slow_requests` (the Log page's slow requests and the traces' slow ones) and `app_status` (releases, open problems, the lookout's findings). An encargo from the lookout is told to verify its numbers with them first.
- **Coding agent:** it no longer gives up for what passes by itself: a dropped connection or a busy AI API is tried again up to 3 more times, a forja's 5xx once more, a run longer than 50 minutes is waited for (up to 6 hours, spending nothing), and a run the cluster failed (etcd, an evicted pod, an image pull) runs once more with the platform's retry.
- **Database:** migration `0065_encargo_preguntas.sql` adds the encargo status `asking` (widening the status check) and the table `encargo_preguntas` (only adds: the previous version never writes nor reads them).
