- **Agents:** each agent works under permissions (Ruta 184): reading the code and the Ruta (always), the platform's views, its app's infrastructure, the sandbox, its preview copies and actions with effect, each off, ask or always (effects never always), limited to some apps if chosen. The subjects are the coding agent, the platform's other agents (by a stable id: `coder`, `diagnostician`, `estimator`, `vigia`…) and each MCP key on its own. They are set on the AI page → Permissions; members see them, administrators change them.
- **Agents:** the defaults keep what agents did before: the coding agent and MCP keys see the platform and their copies, run their sandbox, ask for the infrastructure and do nothing with effect; the diagnostician's infra reading is always only for its failed run's step pods. The old **Run commands in a sandbox** switch is now the coding agent's `sandbox` permission (off where it was off).
- **Agents:** when a tool asks, the coding agent says why and stops without spending; «For you» shows **The agent asks for permission** with **Only this time**, **While this encargo lasts**, **Always, for the app** and **No** (an action with effect: **Do it** / **No**). An administrator gives it, a collaborator may say no; the grants that hold are taken back on the AI page.
- **Agents:** new tools: `infra_read` for the coding agent and `infra_leer` over MCP read the app's pods, recent events, logs (the previous container's too), rollout and verification, read-only, only its own objects and never Secrets; on a computer, its containers and their logs. `copies`/`copias_leer` read its preview copies; `restart_service`, `rerun_branch`, `remake_copy` and `servicio_reiniciar`, `copia_rehacer` act, each use a person's yes. `permiso_pedir` lets an MCP agent give its reason.
- **Agents:** MCP keys' `ejecucion_lanzar` and `ejecucion_reintentar` are actions with effect now: off by default, so an agent that queues or retries branch runs needs a person to set its key's effects to ask, and to say yes each time. Pushing to a branch still runs it as before.
- **Agents:** every use of a permission, request and answer goes to the encargo's history and to the bitácora (what was read or done, never values).
- **Deploy:** `deploy/` changed (the platform's ClusterRole may now read events): run `make deploy` once, or the infrastructure tool says it could not read the events.
